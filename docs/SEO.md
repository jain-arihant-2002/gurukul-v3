# SEO: sitemap & crawler rules

Generated by Next.js metadata routes — no static XML to maintain.

| URL | Source | Rendering |
|---|---|---|
| `/sitemap.xml` | `app/sitemap.ts` | dynamic (`force-dynamic`) |
| `/robots.txt` | `app/robots.ts` | static |

Site origin comes from `lib/site.ts`: `NEXT_PUBLIC_APP_URL`, else `https://$VERCEL_URL`, else `http://localhost:3000`. Set `NEXT_PUBLIC_APP_URL` in production — every URL in the sitemap is absolute.

## What is listed

- Static: `/`, `/about`, `/contact`, `/teacher`
- Catalog pagination: `/courses/page/{1..n}` (12 per page), `/instructors/page/{1..n}` (16 per page)
- Published courses: `/courses/{slug}` — only `status = 'published'`
- Active instructors: `/instructors/{username}` — role `instructor` and `coursesCount > 0`

`/courses` and `/instructors` redirect to their `/page/1` form, so they are deliberately absent (a sitemap must not list redirects). `<lastmod>` uses the row's real `updated_at`; `priority` and `changefreq` are omitted because Google ignores them.

## What is disallowed

`/api/`, `/dashboard`, `/sign-in`, `/sign-up`, `/courses/create`, `/courses/*/edit`, `/courses/*/learn`, `/courses/*/preview`, `/courses/*/success`, `/courses/*/cancelled`, `/instructors/register`, `/instructors/*/edit`.

`robots.txt` only stops crawling, not indexing. Private pages should also carry `export const metadata = { robots: { index: false } }` so a linked URL cannot be indexed — not yet applied to the pages above.

## Page metadata & structured data

| Page | Title | JSON-LD |
|---|---|---|
| `/` | Gurukul — Online Courses and Expert Instructors | `EducationalOrganization`, `WebSite` |
| `/courses/page/{n}` | Gurukul Courses — Browse Online Courses (— Page n) | `BreadcrumbList`, `ItemList` of `Course` |
| `/instructors/page/{n}` | Gurukul Instructors — Meet Our Expert Teachers (— Page n) | `BreadcrumbList`, `ItemList` of `Person` |
| `/instructors/{username}` | {name} — Gurukul Instructor | `BreadcrumbList`, `Person` (with `sameAs`, `worksFor`) |

Helpers live in `lib/seo.ts`, and `components/JsonLd.tsx` escapes `<` so a course or instructor name cannot break out of the script tag. Every page self-canonicalises; out-of-range pagination numbers return `noindex, follow` instead of a page title, since they redirect to page 1.

Route-level `loading.tsx` skeletons are placeholders only — no `<h1>`/`<h2>` and no marketing copy. They are streamed into the initial HTML, so headings there previously produced a second `<h1>` and stale copy on `/` and `/courses/page/1`, and the group-level skeleton leaked the home hero into `/instructors/page/1`.

## Social preview card

`app/opengraph-image.tsx` renders a 1200x630 PNG (dark card, teal brand mark, domain, headline) through `next/og`, built from `lib/og-image.tsx`. Every page declares it explicitly via `socialMetadata()` in `lib/seo.ts`:

```html
<meta property="og:image" content="https://<origin>/opengraph-image"/>
<meta property="og:image:width" content="1200"/>
<meta property="og:image:height" content="630"/>
<meta name="twitter:card" content="summary_large_image"/>
```

It has to be explicit: page-level `openGraph`/`twitter` objects replace the parent's object instead of deep-merging, so relying on the file convention alone silently dropped the image on every page that sets its own title.

The card is generic (same image on every URL). Per-course and per-instructor cards would need `opengraph-image.tsx` inside those dynamic segments with a DB lookup, plus `generateMetadata` on course pages.

## Not yet done

- No `og:image` anywhere — needs a real 1200x630 asset.
- Private pages (`/dashboard`, `/sign-in`, `/courses/*/edit`, …) are `Disallow`ed but still lack `robots: { index: false }`.
- Course detail pages (`/courses/{slug}`) still have no `generateMetadata`; they inherit the root title.
- Footer links `/privacy`, which does not exist yet (404).

## Limits

One `urlset` is emitted. Google's caps are 50,000 URLs / 50 MB uncompressed per file; if `courses` ever exceeds ~50k published rows, split into a `sitemapindex` with one file per content type and point `app/robots.ts` at the index.
